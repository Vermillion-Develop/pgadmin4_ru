.. _ai_tools:

*******************
`Отчеты ИИ`:index:
*******************

**Отчеты ИИ** — это функция, которая предоставляет анализ базы данных и аналитику на основе искусственного интеллекта с использованием больших языковых моделей (LLM). Используйте меню *Инструменты → Отчеты ИИ* для доступа к различным отчетам на базе ИИ.

Функция отчетов на основе ИИ позволяет вам:

 * Создавать отчеты по безопасности для выявления потенциальных уязвимостей и проблем с конфигурацией.
 * Создавать отчеты о производительности с рекомендациями по оптимизации запросов и конфигураций.
 * Проводить анализ архитектурных решений для оценки структуры схемы базы данных и внесения предложений по ее улучшению.

**Предварительные требования**

Перед использованием ИИ-отчетов необходимо убедиться в выполнении следующих условий:

 1. Функции ИИ включены в конфигурации сервера (параметр ``LLM_ENABLED`` имеет значение ``True`` в файле ``config.py``).
 2. Провайдер LLM настроен в разделе :ref:`Настройки → ИИ <preferences>`.

.. note::
 * ИИ-отчеты с использованием облачных провайдеров (Anthropic, OpenAI) требуют активного подключения к интернету. Локальные провайдеры (Ollama, Docker Model Runner) работают без доступа к сети.
 * Использование API может повлечь за собой дополнительные расходы в зависимости от модели тарификации вашего провайдера LLM. Локальные провайдеры (Ollama, Docker Model Runner) бесплатны.
 * Качество и точность отчетов напрямую зависят от выбранного провайдера LLM и настроенной модели.


Настройка ИИ-отчетов
====================

Для настройки ИИ-отчетов перейдите по пути *Файл → Настройки → ИИ* (или нажмите кнопку *Настройки* и выберите раздел *ИИ*).

.. image:: images/preferences_ai.png
    :alt: AI preferences
    :align: center

Выберите предпочтительного провайдера LLM из выпадающего списка:

**Anthropic**
  Используйте модели Claude от Anthropic или любого поставщика API, совместимого с Anthropic.

  * **API URL**: Пользовательский URL-адрес конечной точки API (оставьте пустым для использования значения по умолчанию: https://anthropic.com).
  * **API Key File**: Путь к файлу, содержащему ваш API-ключ Anthropic (можно получить на https://anthropic.com). Этот путь указывает на файловую систему, в которой запущен сервер pgAdmin (например, внутри контейнера при использовании Docker). Префикс ``~`` разворачивается в домашний каталог пользователя, от имени которого запущен процесс сервера pgAdmin. Необязателен при использовании пользовательского URL с провайдером, не требующим аутентификации.
  * **Model**: Выберите одну из доступных моделей Claude (например, claude-sonnet-4-20250514).

**OpenAI**
  Используйте модели GPT от OpenAI или любого поставщика API, совместимого с OpenAI (например, LiteLLM, LM Studio, EXO или другие локальные серверы вывода).

  * **API URL**: Пользовательский URL-адрес конечной точки API (оставьте пустым для использования значения по умолчанию: https://openai.com). Укажите префикс ``/v1``, если этого требует ваш провайдер.
  * **API Key File**: Путь к файлу, содержащему ваш API-ключ OpenAI (можно получить на https://openai.com). Этот путь указывает на файловую систему, в которой запущен сервер pgAdmin (например, внутри контейнера при использовании Docker). Префикс ``~`` разворачивается в домашний каталог пользователя, от имени которого запущен процесс сервера pgAdmin. Необязателен при использовании пользовательского URL с провайдером, не требующим аутентификации.
  * **Model**: Выберите одну из доступных моделей GPT (например, gpt-4).

**Ollama**
  Используйте локально запущенные open-source модели через Ollama. Требуется предварительно запущенный экземпляр Ollama.

  * **API URL**: URL-адрес вашего сервера Ollama (по умолчанию: http://localhost:11434).
  * **Model**: Введите имя модели Ollama для использования (например, llama2, mistral).

**Docker Model Runner**
  Используйте модели, запущенные во встроенном механизме запуска моделей Docker (доступно в Docker Desktop 4.40+). API-ключ не требуется.

  * **API URL**: URL-адрес API Docker-контейнера для запуска моделей (по умолчанию: http://localhost:12434).
  * **Model**: Выберите одну из доступных моделей или введите пользовательское название модели.

.. note:: Вы также можете использовать провайдера *OpenAI* с пользовательским URL-адресом API для любых целей. Совместимые с OpenAI конечные точки включают Docker Model Runner и другие локальные серверы вывода.

После настройки провайдера нажмите кнопку *Сохранить* для применения изменений.

Обработка данных и конфиденциальность
=====================================

Когда настроен облачный провайдер LLM, pgAdmin передает информацию о вашей базе данных поставщику API. В зависимости от используемой функции, передаваемые данные могут включать определения схем (имена таблиц, столбцов, индексов и ограничений), типы данных, параметры конфигурации сервера и базы данных из файла ``pg_settings``, текст самого запроса, а также план его выполнения. Инструмент *ИИ-помощник* в Редакторе запросов также позволяет выполнять запросы к базе данных в режиме транзакции «только для чтения» с ограничением в 1000 строк; при этом в ответ могут включаться реальные данные строк, если ИИ-помощник сочтет их необходимыми для формирования ответа.

Никакие данные не передаются до тех пор, пока вы сами не воспользуетесь функцией ИИ. Данные вообще не отправляются в сеть, если провайдеры не настроены (настройка по умолчанию), если функции ИИ принудительно отключены администратором с помощью параметра ``LLM_ENABLED``, либо если используется локальный провайдер, такой как Ollama или Docker Model Runner.

Каждый провайдер обрабатывает эти данные в соответствии с собственными условиями обслуживания, политикой конфиденциальности и требованиями применимого законодательства, а также размещает вычислительную инфраструктуру в выбранных им локациях. Если ваша деятельность регулируется требованиями к месту хранения данных, политиками безопасности или отраслевыми стандартами обработки метаданных баз данных, перед началом работы ознакомьтесь как с условиями поставщика, так и с внутренними регламентами вашей организации.

Провайдеры, перечисленные в pgAdmin, соответствуют API, с которыми программа умеет взаимодействовать. Их наличие в списке не является прямой рекомендацией, и ни один из них не включен по умолчанию.


Отчеты по безопасности
======================

Отчеты по безопасности анализируют ваш сервер PostgreSQL, базу данных или схему на предмет потенциальных уязвимостей и ошибок конфигурации.

Для создания отчета по безопасности:

1. В дереве *Браузер* выберите базу данных или схему.
2. В верхнем меню выберите *Инструменты → Отчеты ИИ → Безопасность* или нажмите правой кнопкой мыши по объекту и выберите пункт *Безопасность* из контекстного меню.
3. Отчет будет сформирован и отображен на новой вкладке.

.. image:: images/ai_security_report.png
    :alt: AI security report
    :align: center

**Область охвата отчета по безопасности:**

* **Уровень сервера**: Анализ конфигурации сервера, настроек аутентификации, ролей и прав доступа.
* **Уровень базы данных**: Проверка настроек безопасности конкретной базы данных, ролей с доступом к ней и прав доступа к объектам.
* **Уровень схемы**: Рассмотрение прав доступа к схемам, владельцев объектов и механизмов контроля доступа.

Каждый отчет включает в себя:

* **Результаты проверки безопасности**: Выявленные уязвимости или бреши в защите.
* **Оценка рисков**: Уровень серьезности для каждого нарушения (Критический, Высокий, Средний, Низкий).
* **Рекомендации**: Конкретные действия по устранению проблем безопасности.
* **Лучшие практики**: Общие рекомендации по обеспечению безопасности PostgreSQL.


Отчеты о производительности
===========================

Отчеты о производительности анализируют быстродействие запросов и параметры конфигурации, а также содержат рекомендации по оптимизации.

Для создания отчета о производительности:

1. В дереве *Браузер* выберите базу данных или схему.
2. В меню выберите *Инструменты → Отчеты ИИ → Производительность* или нажмите правой кнопкой мыши по объекту и выберите пункт *Производительность* из контекстного меню.
3. Отчет будет сформирован и отображен на новой вкладке.

**Область охвата отчета о производительности:**

* **Уровень сервера**: Анализ параметров конфигурации сервера, использования ресурсов и общих показателей производительности.
* **Уровень базы данных**: Анализ конфигурации конкретной базы данных, производительности запросов, эффективности использования индексов и статистики таблиц.

Каждый отчет включает в себя:

* **Показатели эффективности**: Ключевые метрики производительности и статистика.
* **Анализ конфигурации**: Обзор влияющих на быстродействие параметров конфигурации.
* **Оптимизация запросов**: Рекомендации по оптимизации медленных SQL-запросов.
* **Рекомендации по индексам**: Предложения по добавлению, удалению или изменению структуры индексов.
* **Планирование мощностей**: Тенденции использования ресурсов и рекомендации по масштабированию.


Отчеты об анализе архитектуры (Design Review)
=============================================

Отчеты об анализе архитектуры содержат аудит структуры схемы базы данных и рекомендации по ее улучшению с учетом принципов нормализации, правил именования и передовых практик.
